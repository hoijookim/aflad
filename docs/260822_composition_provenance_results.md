## Q1 (막힘 해제) — **저자 배포본입니다.** 지금 원고 서술이 틀렸습니다

현재 링크 상태는 **재생성본을 가리킵니다** — 그래서 오해하기 쉬운 자리였습니다.

```
masks -> masks_regen        (심볼릭 링크, 2026-08-16 22:48)
masks_orig    23,884장      파일 시각 2024-02-06   ← 저자 배포본 현물
masks_author  23,884장      2026-08-16 21:53       ← 저자 배포본 백업
masks_regen    1,080장      2026-08-16 22:49       ← 재생성본 (부분)
```

**그런데 보고 수치를 낸 `csad_pseudo_seg/` 는 전부 링크 생성보다 먼저 만들어졌습니다.**

| 범주 | 생성 시각 |
|---|---|
| breakfast_box | 2026-08-15 16:21 |
| juice_bottle | 2026-08-15 16:23 |
| screw_bag | 2026-08-15 16:27 |
| splicing_connectors | 2026-08-15 16:29 |
| pushpins | **2026-08-16 10:33** (3×5 재생성) |
| ← 심볼릭 링크 | **2026-08-16 22:48** |

가장 늦은 것(8/16 10:33)이 링크(8/16 22:48)보다 **12시간 이릅니다.** 요청서에 적어 주신
판정 기준 그대로 — **재생성이 채점 이후이므로 보고 수치는 저자 배포본입니다.**

보강 증거 둘:
- 재생성본은 **1,080장뿐**이라 저자 배포본 23,884장을 대체할 수 없습니다(부분 재생성).
- `csad_regen.py` 독스트링이 직접 적습니다 — *"지금까지는 저자가 배포한 마스크를 그대로 썼다.
  재생성의 목적은 (1) 재현성 (2) 개선 여지"*. 재생성은 **탐색이었고 채택되지 않았습니다.**

### 원고 수정

지금 원고는 *"CSAD 의 공개 구현과 설정으로 의사 레이블을 생성한다"* 인데 **사실과 다릅니다.**
요청서의 두 갈래 중 **전자**로 가야 합니다:

> CSAD[9]가 공개한 구성 요소 의사 레이블을 쓴다. 그 생성 절차는 …(부록 A)

Data Availability 도 "우리가 생성" 이 아니라 "CSAD 배포본 사용" 이 됩니다.

### 타임스탬프 추론에서 끝내지 않고 **재생성으로 증명**했습니다

링크를 복원한 뒤(`csad_regen.py --restore`) 저자 마스크로 `build_inputs.py` 를 다시 돌려
보고본과 픽셀 단위로 대조했습니다.

| 범주 | 결과 |
|---|---|
| breakfast_box · juice_bottle · pushpins · screw_bag · splicing_connectors | **5범주 전 장 비트 동일** |

**저자 배포본이 맞습니다 — 추론이 아니라 재생성으로 확정됐습니다.**

### ⚠ 함정 두 개를 찾아 둘 다 고쳤습니다

**함정 1 — `masks -> masks_regen` 링크가 남아 있었습니다**(`--restore` 미실행). 지금 누가
`build_inputs.py` 를 돌리면 **부분 재생성본 1,080장을 조용히 씁니다.**
→ **복원했습니다.** `masks` 가 다시 저자본 23,884장(2024-02-06)이고 `masks_regen`(1,080장)과
`masks_author` 백업은 보존했습니다.

**함정 2 — 기각된 E10 이 기본값이었습니다.** 아래 별도 절로 뺐습니다. 이쪽이 더 큽니다.

## ⚠ Q1 에서 딸려 나온 것 — **개선 ② 는 보고 수치에 들어 있지 않습니다**

요청서가 "논문에 없는 구성 분기 설계 요소 4건" 중 ②로 든
**`splicing — 커넥터 쌍을 x 무게중심으로 좌/우 분리(클래스 3 추가)`** 는
**방법의 일부가 아닙니다. 사전등록 후 기각된 탐색입니다.**

재생성 대조에서 splicing 만 **360장 중 359장이 달랐고**, 클래스 수도 보고본 3개(0,1,2) vs
재생성 4개(0,1,2,3) 로 갈렸습니다. 파고들었더니:

| | 시각 |
|---|---|
| 보고 의사레이블 (`csad_pseudo_seg/splicing_connectors`) | 2026-08-15 16:29 |
| 보고 점수 (`psad_scores_*_hc_tta_merge_test.npz`) | 2026-08-17 16:44 |
| **`splicing_split_connectors` 커밋** | **2026-08-17 20:57** |

커밋 제목이 `E10 splicing 좌/우 분리 **시도**` 이고, 같은 날 판정이 남아 있습니다
(`PREREG_branch_improvement.md:545`):

> **E10 판정 결과 — 기각** (2026-08-17)
> | 구성 | 최대 \|z_robust\| | CV |
> | 기존 레이블 (클래스 2) | **6.29** | 0.133 |
> | 좌/우 분리 (클래스 3) | **54.60** | 0.960 |

val 정상 점수 꼬리가 **8.7배 악화**해 기각됐습니다. **절차는 정상입니다** — 사전등록하고,
val 기준으로 재고, 기각했습니다.

**문제는 코드가 그 기각을 반영하지 않았다는 것입니다.** `build_inputs.py:161` 의
`elif cat == "splicing_connectors": lab = splicing_split_connectors(lab)` 에 **게이트가
없어서**, 지금 재생성하면 기각된 변형이 기본으로 나옵니다.

→ **고쳤습니다.** `PSAD_SPLICING_SPLIT` 로 게이팅하고 기본을 껐습니다. 고친 뒤 재생성하니
splicing 도 **전 장 비트 동일**합니다.

### 원고에 미치는 영향

§3.1.3 에 공개하실 개선은 **4건이 아니라 3건**입니다 — ① 트레이 격자 · ③ 혼동쌍 병합 ·
④ 회전 TTA. **② 는 빼야 합니다.** 넣으면 쓰지 않은 것을 방법으로 서술하게 됩니다.

기각 사실 자체는 쓸 데가 있습니다 — §3 이나 부록에 "구조적 논거가 있어도 val 기준을 통과하지
못하면 채택하지 않았다" 는 예로 한 줄 넣으면 test-free 절차의 엄격함을 보여줍니다.

## Q2 — 표 A1 의 K 는 **7 / 6 / 16 / 6 / 3** 입니다

보고 수치를 낸 `csad_pseudo_seg/{cat}/pred_*.png` 전수에서 실제 라벨 합집합을 뽑았습니다.

| 범주 | **실제 사용 클래스** | 라벨 | `NUM_CLS` 선언 = 분할기 출력 채널 |
|---|--:|---|--:|
| breakfast_box | **7** | 0–6 | 7 ✓ |
| juice_bottle | **6** | 0–5 | 9 |
| **pushpins** | **16** | 0–15 | **26** |
| screw_bag | **6** | 0–5 | 7 |
| splicing_connectors | **3** | 0–2 | 10 |

**추측하신 것이 맞습니다.** 26 은 PSAD 가 하드코딩한 배열 크기이고 실제는 16(15칸+배경)입니다.
결정적 증거로 `csad_pseudo_seg/pushpins_grid5x5_old/`(5×5 시절 산출물)가 **정확히 26 클래스**
(0–25)입니다.

**다만 예상보다 넓습니다** — 선언과 실제가 어긋나는 것이 pushpins 하나가 아니라 **5범주 중
4곳**입니다(breakfast_box 만 일치). 분할기는 `NUM_CLS` 채널로 만들어지고 남는 채널은 학습
목표에 없어 활성화되지 않습니다. 시드 42/43/44 체크포인트 모두 선언값과 같은 채널 수입니다.

캡션에 넣으실 문구: **"K 는 의사 레이블에 실제로 나타나는 구성 요소 클래스 수이며, 분할기의
출력 채널 수(PSAD 구현이 고정한 배열 크기)와 다르다."**

`build_inputs.py` 독스트링의 `각 범주 클래스 합집합(7/6/26/6/3)` 도 **pushpins 만** 낡았습니다
— 나머지 넷은 맞습니다.

## Q3 — 융합·분기 산출물은 전부 같은 설정입니다. 다만 두 가지를 구분해야 합니다

`testfree_supplements_3seed.json` 의 config 가 명시합니다:
`"psad": "hc + 혼동쌍 병합 + 회전 TTA(screw_bag)"`.
주 산출물들도 `psad_kind: hc_tta_merge` 로 기록돼 있습니다.

### 구분 1 — 파일명의 `tta` 는 플래그이고, 실제 TTA 는 **screw_bag 에만** 걸립니다

```python
TTA_ADOPTED = {"screw_bag"}                        # score_psad.py:113
...
if tta and cat in TTA_ADOPTED:                     # :227
    mask = tta_mask(...)
```

다섯 범주 파일이 모두 `_hc_tta_merge` 이름을 갖지만 나머지 넷은 TTA 를 통과하지 않습니다.
병합도 screw_bag `c4↔c5` 하나뿐입니다(다른 범주는 임계값 미달).

### 구분 2 — **부록 C1/C2 는 구성 분기를 쓰지 않습니다**

물어보신 두 자리의 답이 갈립니다.

| 자리 | 설정 |
|---|---|
| 표 4 **구성 분기 단독 열** | `hc_tta_merge` ✓ — ①②③④ 가 전부 작용합니다 |
| **부록 C2 개수 readout** | **해당 없음** — frozen DINOv3-L L17 특징 위의 KMeans/patch-memory readout 이라 CSAD 의사 레이블을 아예 읽지 않습니다 |

부록 C1(25칸 격자)도 같습니다 — 캐시만 씁니다. 즉 트레이 격자·좌우 분리·혼동쌍 병합·회전 TTA
넷은 **표 2·3·4 와 부록 B1, 그림 9 에만** 작용하고 **부록 C 에는 닿지 않습니다.**
§3.1.3 에 개선을 서술하실 때 그 범위를 그렇게 적으시면 정확합니다.

## Q4 — **29 ms 에 회전 TTA 가 반영돼 있지 않습니다.** 실측했습니다

`fps_comparison_260621.json` 의 구성 분기 항목이 `"src": "direct measure resnet101+segCNN
forward"` 입니다 — **단일 forward** 이고 TTA 가 빠져 있습니다.

RTX 5090 / batch 1 / FP32 / 512×512 / warmup 20 · 반복 100 으로 분할기 forward 만 격리해
쟀습니다(논문 11.2 ms 와 같은 층위).

| | ms |
|---|--:|
| 분할기 forward 1회 | **6.87** |
| 분할기 forward 4회 (회전 TTA) | **27.48** |
| TTA 가 더하는 몫 | **+20.61** |

| | 구성 분기 | 3분기 합 |
|---|--:|--:|
| 다른 4범주 | 11.2 | **29** |
| **screw_bag** | **31.8** | **약 49.6** |

**screw_bag 은 보고값보다 71% 느립니다.**

### 이건 각주로 안 끝날 수 있습니다

§4.5 가 `SALAD(약 57 ms)보다 두 배 가까이 빠르면서` 라고 씁니다. screw_bag 에서는
**49.6 vs 57 로 1.15배**입니다. "두 배 가까이" 가 그 범주에서는 성립하지 않습니다.

세 가지 중 고르시면 됩니다.

1. **범위로 보고** — "이미지당 29 ms(회전 TTA 를 쓰는 screw_bag 은 약 50 ms)". 가장 정직하고,
   TTA 가 왜 필요한지를 §3.1.3 에서 이미 설명하므로 자연스럽습니다.
2. **가중 평균으로 보고** — 5범주 평균이면 (29×4 + 49.6)/5 = **33.1 ms**. 단일 수치를 유지하되
   TTA 를 반영합니다. 그래도 SALAD 대비 1.72배라 "두 배 가까이" 는 약해집니다.
3. **TTA 미적용 경로를 함께 보고** — TTA 없이도 hc 는 동작하므로 "TTA 를 끄면 29 ms" 를 밝히고
   정확도 차이를 병기.

저는 **1** 을 권합니다. 표 5 캡션에 한 줄이면 되고, 범주별로 다르다는 사실 자체가 설계를
설명합니다(분산 감소기를 필요한 범주에만 켰다).
