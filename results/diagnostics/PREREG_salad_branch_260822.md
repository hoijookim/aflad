# 사전등록 — SALAD 를 융합 분기로 넣는 실험 (260822, 5090)

**이 문서는 test 를 보기 전에 고정한다.** 아래 결정 규칙을 먼저 확정하고, 그 다음에 test 를
**한 번만** 평가한다. 결과를 보고 규칙을 바꾸지 않는다.

배경 — 260816 에 `hc × test-free 0.9807` 을 철회했다. 점수 계산은 test-free 였으나
**구성 선택**(정규화 8종 × 집계 4종 × 분기 조합 7종 × 클리핑 4종)을 test AUROC 로 비교해
최고치를 골랐기 때문이다. L17 계층 선택도 같은 구조였다(260822 요청 ⑦).
이 실험은 그 재발을 구조적으로 막기 위해 사전등록한다.

**주장은 test-free inductive 다. 테스트셋으로는 학습도, 통계 산출도, 설정 선택도 하지 않는다.
테스트셋은 최종 추론 1회에만 쓴다.**

---

## 0. 왜 이 실험을 하는가

`docs/260822_combination_history.md` 가 기록한 조합 히스토리에서, **구성 자리에 SALAD 를
넣는 것이 단일 추가 중 가장 컸다(+1.33pp, `reports/countgd/combo_sweep.json`)**.
그러나 그 수치는 (a) 구 프로토콜(V4 포함, 중첩 CV)에서 나왔고 (b) test 로 비교한 것이라
현행 test-free 주 설정에 그대로 옮길 수 없다.

4090 에서는 이 실험이 막혀 있었다 — "SALAD 는 val 점수가 없고 체크포인트도 없다.
재학습 ~22h + 추론 2h = 약 24시간"(`docs/260822_branch_swap_results.md`).
**5090 에는 학습 체크포인트 15개(시드 42/43/44 × 5범주)와 합성맵(train/validation/test)이
모두 있다.** 재학습 없이 추론만으로 답할 수 있다.

## 0-1. 선결 확인 — annotation-free 주장과 충돌하지 않는다

SALAD 합성맵은 사람 어노테이션이 아니다. `external/SALAD/create_pseudo_labels.py` 가
**SAM-HQ(`sam_model_registry`) + DINO(`DinoFeaturizer`) + KMeans** 로 자동 생성하며,
저자 배포본(`download_composition_maps.sh`)은 그 산출물이다. 따라서 SALAD 신호를 분기로
써도 논문 제목의 annotation-free 를 깨지 않는다. **이 확인은 test 와 무관하다.**

## 1. 고정하는 설계 (D1~D5)

### D1 — 어떤 SALAD 신호를 쓰나 : `score_comp` 만

`dump_scores` 가 내는 4종 중 선택은 **아키텍처 근거**로 한다. 성능은 보지 않는다.

| 신호 | 채택 | 근거 |
|---|:--:|---|
| `score_comp` (구성 지도 기반) | **채택** | 구성 축 신호. 주 설정의 구성 분기(PSAD-hc)와 같은 자리 |
| `score_combined` | 기각 | EAD 유사 + mahalanobis + comp 의 합 → 분기 1·2 와 중복. "세 분기 직교" 논리를 깬다 |
| `score_img` | 기각 | EAD 유사 → 재구성 분기와 중복 |
| `score_maha` | 기각 | 패치 특징 거리 → 패치 메모리 분기와 중복 |

이는 260816 에 hcp 를 4번째 분기로 넣지 않은 것과 **같은 기준**이다
(구성 분기 내부 PatchCore 가 독립 PC 분기와 중복되므로 미채택).

### D2 — 어떤 배치(arm)를 재나 : 셋 다 재고, 고르지 않는다

| arm | 구성 | 성격 |
|---|---|---|
| **M** (주 설정) | EAD + PC + PSAD-hc | 기준선 |
| **A** (치환) | EAD + PC + **SALAD_comp** | 구성 자리 교체 |
| **B** (추가) | EAD + PC + PSAD-hc + **SALAD_comp** | 4분기 |

세 arm 을 **전부 보고한다.** "최고를 고른다"는 절차는 없다 —
그것이 0.9807 을 만든 절차다. 이 실험은 `pc_backbone_swap`(패치 메모리 자리를 5종으로
갈아끼우고 전부 보고)과 같은 성격의 **분기 자리 ablation** 이다.

### D3 — 정규화·가중·집계 : 주 설정 정의 그대로, 탐색 없음

- z-정규화: **공식 검증 분할의 정상 표본** 평균/표준편차. 로그·로버스트·클리핑 **없음**.
- 가중: **고정 등가중** (A/M 은 1,1,1 · B 는 1,1,1,1). 가중 탐색 없음.
- 집계: 단순 합.
- test 통계는 어느 단계에도 들어가지 않는다.

### D4 — 시드 : {42, 43, 44}, 전 분기 동시 변동

정본 문서의 "엄격" 규약을 따른다. SALAD 체크포인트도 같은 세 시드가 있다.

### D5 — SALAD 점수 산출 : test 와 val 을 같은 실행에서

`external/SALAD/dump_scores_valtest.py`. val 만 새로 뽑아 기존 test 와 짝지으면
**서로 다른 추론 실행의 val/test 를 섞게 된다** — 커밋 0a96668 이 EAD seed42 에서
고친 결함과 같은 형태다. 정규화 상수(teacher/map/score/mahalanobis)를 한 번 계산해
test·val 양쪽에 그대로 쓰고, RNG 를 고정한다.

정규화 상수의 출처는 전부 train 또는 validation 이다(코드 감사 완료):
`teacher_normalization`←train, `map_normalization`←validation,
`score_normalization`←validation, `extract_features_mahalanobis`←train,
`map_normalization_mahalanobis`←validation. `test_set` 은 채점에만 등장한다.

## 2. 판정 규칙 — **test 를 보기 전에 확정**

주 설정을 바꾸려면 **아래 둘을 모두** 만족해야 한다. 하나라도 어긋나면 바꾸지 않는다.

**(가) val 전용 기준.** 새 분기가 z-정규화를 망가뜨리지 않아야 한다.
논문이 이미 쓰는 기준을 그대로 적용한다(`PREREG_branch_improvement.md` §E2 판정 지표):
- 검증 정상 점수 꼬리 **최대 |z_robust|** 가 현행 구성 분기(PSAD-hc)보다 **나쁘지 않을 것**
- ~~검증 정상 점수 **변동계수(CV)** 가 현행보다 **나쁘지 않을 것**~~ → **아래 수정 참조**

> ### 수정 1 (2026-08-22, **test 를 열기 전**) — CV 기준을 철회한다
>
> CV = std/|mean| 는 **원점 이동에 불변이 아니다.** SALAD 는 내부적으로
> `score_normalization`(validation 기준)으로 `score_comp` 의 val 평균을 0 으로 만들어 둔다.
> 그래서 CV = std/0 으로 **발산한다**(실측 2.1e+08). 이것은 분기 품질이 아니라
> **지표가 그 분기에 적용 불가**임을 뜻한다 — 서로 다른 내부 정규화를 가진 분기들의 CV 를
> 비교하는 것은 애초에 사과 대 오렌지다.
>
> 반면 꼬리 **|z_robust| = |(v − median)/(1.4826·MAD)| 의 최댓값**은 같은 데이터의
> median/MAD 로 재므로 **평행이동·스케일 양쪽에 불변**이고, 분기마다 내부 정규화가 달라도
> 비교가 성립한다. 또한 PREREG 가 지표를 꼬리로 옮긴 **기전적 이유**(val 이상치 한 장이
> 표준편차를 부풀려 그 분기가 꺼진다)와 직접 맞닿아 있다.
>
> 따라서 **(가)는 꼬리 기준 단독**으로 판정한다. CV 는 참고로 병기하되 판정에 쓰지 않는다.
>
> 이 수정의 근거는 **지표의 수학적 성질**이며 어떤 결과값과도 무관하다. test 는 아직 열지
> 않았고, val 통계만으로 확인했다. 수정 사실과 이유를 여기 남기는 것 자체가 사전등록의 일부다.

> 이 기준을 쓰는 이유는 기전이다 — val 이상치 한 장이 표준편차를 부풀리면 그 분기의
> test z-점수가 통째로 줄어 사실상 분기가 꺼진다. 260822 계층 감사에서 **꼬리와 CV 가
> 서로 다른 계층을 고르는 경우**(L17 vs L8)가 이미 나왔으므로, **둘 다** 요구한다.

**(나) 효과 크기.** test L+S 차이가 **주 설정 시드 표준편차의 2배(2 × 0.0011 = 0.0022)를
초과**할 것. 그 이하는 잡음으로 간주하고 "차이 없음"으로 보고한다.

### 결과별 처리 (미리 선언)

| (가) val 기준 | (나) test 효과 | 처리 |
|---|---|---|
| 통과 | 초과 | **개선으로 채택.** 주 설정 교체를 저자에게 제안 |
| 통과 | 미달 | "동등" 보고. 주 설정 유지(단순한 쪽 우선) |
| **불통과** | **초과** | **채택하지 않는다.** "test 는 A 를 선호하나 선언한 기준이 반대이므로 바꾸지 않는다"를 그대로 보고한다 |
| 불통과 | 미달 | 기각. 음성 결과로 기록 |

세 번째 행이 이 사전등록의 핵심이다. 그 상황에서 채택하면 그것이 곧 test 기반 선택이다.

### 부수 선언

- arm B(4분기)가 A 보다 좋아도, **분기 수를 늘리는 것 자체가 비용**이다(지연·복잡도·
  "세 분기 직교" 서사). B 는 +0.0022 초과에 더해 **A 보다도 0.0022 초과**해야 채택 후보가 된다.
- SALAD 는 표 4 의 **기준선**이기도 하다(0.9469). 그것을 우리 분기로 흡수하면
  "기준선을 부품으로 쓴다"는 서술이 필요하며, 이는 성능과 무관한 **정직성 요건**이다.
  채택 시 §3·§4 에 명시한다.
- 실패해도 버리지 않는다. 조합 히스토리의 +1.33pp 가 현행 프로토콜에서 재현되지 않으면
  그 자체가 **"구 프로토콜 이득의 상당 부분이 절차에서 나왔다"**는 증거다.

## 2-1. 사전 예측 기록 (2026-08-22, **test 를 열기 전**)

val 진단이 끝난 시점에 무엇을 예상하는지 적어 둔다. 맞든 틀리든 남긴다 —
사후에 "그럴 줄 알았다"고 말하지 않기 위해서다.

**관찰(val 전용).** `score_comp` 의 검증 정상 분포가 무겁다. 정상 이미지의 7~33% 가
|z_robust| > 5 이고(PSAD-hc 는 0~2장), 상위 3장을 빼도 최댓값이 8~84 로 남는다.
소수 이상치가 아니라 분포 형태다.

**정정.** 처음에 "SALAD 는 분위수 기반 정규화를 쓰므로 자기 안에서는 문제가 없고 우리
프로토콜과만 안 맞는다"고 적었는데 **틀렸다.** `score_normalization` 은
`q_seg_start = np.mean(comp_scores)`, `q_seg_end = np.std(comp_scores)` 로
**우리 융합과 정확히 같은 mean/std 방식**이다(분위수를 쓰는 것은 맵 수준
`map_normalization` 뿐이다). 두 곳의 스킴은 같다.

**예측.**
1. arm A(치환)가 arm M(주 설정)보다 **나쁠 것**이다. SALAD 최종 점수는
   `score_img + score_maha + score_comp` 인데 comp 항이 눌려도 나머지 둘이 지탱한다.
   arm A 는 구성 자리를 통째로 `score_comp` 에 맡기므로 그 완충이 없다.
2. 특히 **논리 축**에서 손실이 클 것이다 — 구성 분기가 담당하는 축이다.
3. arm B(추가)는 arm M 과 큰 차이가 없을 것이다. PSAD-hc 가 남아 있어 완충이 있고,
   눌린 SALAD_comp 항이 기여를 거의 못 한다.

**이 예측은 판정 규칙이 아니다.** 판정은 §2 표 그대로다. 예측이 맞아도 (가) 불통과이면
채택하지 않고, 예측이 틀려도 규칙은 바뀌지 않는다.

## 3. 실행 계획

1. `dump_scores_valtest.py` 로 15조합(시드 3 × 범주 5) test+val 덤프. RNG 고정.
2. 덤프 무결성 확인 — test N 이 EAD npz 와 같고 정렬 규약(defect_class, filename)이 일치할 것.
   **val N 이 PC/EAD val 과 같을 것**(breakfast 62 / juice 54 / pushpins 69 / screw 60 / splicing 60).
3. val 전용 진단 (가) 산출 — **여기까지 test 를 열지 않는다.**
4. 판정 규칙을 이 문서에서 다시 읽고, 그 다음 test 1회 평가.
5. 결과를 표로 보고(세 arm 전부). 채택/미채택은 §2 표대로.

산출물 예정: `reports/countgd/salad_branch_prereg_260822.json`
