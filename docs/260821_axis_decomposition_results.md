## 표준편차 문제 — 2-멤버 급을 함께 넣으면 해결됩니다

요청서에서 지적하신 대로 3-멤버 동종은 시드를 멤버로 소진해 시드 std 가 없습니다.
(a) 로 가되, **2-멤버 급을 함께 보고**하시길 권합니다. 거기서는 이종·동종 양쪽에서 조합이
3개씩 나와 **양쪽 다 std 가 정직하게 잡히고**, 멤버 수가 맞아 통제도 더 깨끗합니다.

| 구성 (2-멤버) | L+S | std |
|---|--:|--:|
| **이종 2분기** (EAD+PC, EAD+구성, PC+구성 × 3시드) | **0.9384** | 0.0279 |
| 동종 2× 구성 (시드쌍 3개) | 0.9016 | 0.0047 |
| 동종 2× EAD (시드쌍 3개) | 0.8980 | 0.0015 |
| 동종 2× PC (시드쌍 3개) | 0.7921 | 0.0010 |

멤버 수를 2로 맞춘 상태에서 이종이 동종보다 **+0.0368** 높고, 양쪽 다 std 가 있습니다.
3-멤버 행은 단일 값 + 부트스트랩 CI 로 두고, 2-멤버 행이 std 를 담당하는 구성을 권합니다.

부수적으로 이종 2분기의 std(0.0279)가 동종(0.0010~0.0047)보다 **한 자릿수 큽니다** — 조합에
따라 성능이 크게 갈린다는 뜻이고(EAD+구성 0.9633 vs EAD+PC 0.9023), **어떤 신호를 섞느냐가
중요하다**는 §4.4 의 보완 논의와 같은 이야기입니다.

# 적대적 검수 — 제가 틀린 것과 주의할 것

요청하신 대로 셋을 전부 되짚었습니다. **결론을 바꾸는 것 1건, 제 서술 오류 1건**이 나왔습니다.

## 검수 1 (결론에 영향) — 계층 선택이 개수축을 누르고 있습니다

프로토콜이 **구조 AUROC 가 최대인 계층**에서 개수축을 읽습니다. 개수축 자체 최적 계층과
비교하면 차이가 큽니다.

| 범주 (DINOv3 S/B/L) | 구조 최적 계층에서 | 개수축 최적 계층에서 |
|---|---|---|
| breakfast_box | 0.717 / 0.807 / 0.823 (상승) | 0.802 / 0.807 / 0.823 (상승) |
| pushpins | 0.602 / 0.545 / 0.521 (하락) | 0.615 / 0.589 / 0.616 (평평) |
| screw_bag | 0.576 / 0.580 / 0.577 (평평) | 0.576 / 0.580 / 0.586 (미세 상승) |
| **splicing_connectors** | 0.858 / 0.740 / 0.874 (비단조) | **0.912 / 0.942 / 0.995 (단조 급상승)** |

**splicing_connectors 의 해석이 뒤집힙니다.** 구조 최적 계층에서는 "높지만 들쭉날쭉" 으로
보이는데, 자기 계층에서 보면 **규모를 따라 0.91→0.99 로 오릅니다.** §5.1 의 "이질 부품에서는
개수 위반이 국소 흔적을 남긴다" 를 훨씬 강하게 뒷받침합니다.

**다만 이 열을 표에 그대로 실으시면 안 됩니다.** 개수축 최적 계층 선택은 **test 로 계층을
고르는 것**입니다. 진단용으로만 쓰시고, 표에는 기존 프로토콜(구조 최적) 값을 두시길 권합니다.

> 관련해 하나 더 — **기존 프로토콜의 "구조 최적 계층" 도 test 기반 선택입니다.** 부록 C 캡션이
> 그 사실을 밝히고 있고(`구조 탐지 평균이 가장 좋은 계층에서`) 메커니즘 분석이지 방법 설정이
> 아니므로 test-free 원칙 위반은 아닙니다. 다만 심사자가 짚을 수 있는 자리라, 부록 C 도입부에
> "이 선택은 계층 효과를 통제하기 위한 것이며 주 설정의 계층(L17)은 이와 무관하게 고정" 한 줄이
> 있으면 안전합니다.
