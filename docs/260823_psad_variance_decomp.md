# 260823 — PSAD 재구축 차이의 **원인 분해**: 기계가 아니다 (5090)

코드 `scripts/psad_rebuild/psad_variance_decomp.py` · 결과 `reports/countgd/psad_variance_decomp.json`
선행 `docs/260823_psad_3way_compare.md`(원인 서술 정정 대상)

## 0. 왜 — 3자 대조가 원인을 **재지 않고 적었다**

3자 대조는 260816(4090) 재구축본과 5090 재구축본의 PSAD 분기 점수가 **Spearman 0.938** 로
갈린다는 것을 냈다. 그리고 원인을 이렇게 적었다:

> 시드는 고정했으나 GPU 커널·cuDNN 알고리즘 선택이 **기계마다** 다르다.

**그것을 재지 않았다.** 그럴듯한 기전을 적었을 뿐이다. 같은 기계·같은 시드로 두 번 돌려도
0.938 이 나온다면 원인은 기계가 아니고, 그러면 "다른 기계에서 재현되지 않는다" 는 서술이
틀린다. 문서의 제목 자체가 "기계 간에 재현되는가" 라 이 귀속이 결론을 좌우한다.

## 1. 통제군은 이미 있었다 — 추가 학습 0

두 재구축본 **모두 시드 42/43/44** 를 가지고 있다. 그러면 세 종류의 거리를 잴 수 있다.

| 이름 | 쌍 | 무엇이 다른가 |
|---|---|---|
| cross_seed | 같은 재구축본, 다른 시드 | 시드만 |
| cross_rebuild | 다른 재구축본, 같은 시드 | 기계 + 재실행 |
| cross_both | 다른 재구축본, 다른 시드 | 전부 |

## 2. 결과 — **셋이 같다**

```
비교 종류               쌍    Spearman    Kendall    |Δ 분기 L+S|
시드만 다름             30      0.9381     0.8172        0.0107
재구축만 다름           15      0.9378     0.8169        0.0082
둘 다 다름              30      0.9374     0.8144        0.0115
```

`cross_rebuild − cross_seed = −0.0003`. 세 자리에서 구별되지 않는다.

읽히는 것이 둘이다.

**(가) 기계는 아무것도 설명하지 않는다.** 시드만 바꾼 것과 기계까지 바꾼 것이 같은 거리다.
바꿔 말하면 **5090 재구축본은 260816 재구축본의 "또 하나의 시드" 와 통계적으로 구별되지
않는다.** 이건 재현성이 나쁘다는 뜻이 아니라 오히려 그 반대다 — 다른 기계의 산출물이
기존 시드 앙상블 **안에** 들어온다.

**(나) 교란을 겹쳐도 더 나빠지지 않는다.** 두 원인이 각각 실재하고 독립이라면 둘을 동시에
바꾼 cross_both 가 더 낮아야 하는데, 0.9374 로 같다. **어떤 교란이든 같은 바닥(≈0.938)에
포화한다** — 학습이 여러 등가 해 중 하나에 안착하고, 시드든 기계든 그저 "다른 해를 고르게
하는 한 가지 방법" 일 뿐이라는 신호다.

지표 수준에서는 오히려 **재구축 차(0.0082)가 시드 차(0.0107)보다 작다.**

### 범주별

| 범주 | 시드만 | 재구축만 | 차 |
|---|--:|--:|--:|
| breakfast_box | 0.9342 | 0.9369 | +0.0026 |
| juice_bottle | 0.9334 | 0.9186 | −0.0148 |
| pushpins | 0.8998 | 0.8970 | −0.0028 |
| screw_bag | 0.9272 | 0.9405 | +0.0133 |
| splicing_connectors | **0.9958** | **0.9960** | +0.0002 |

부호가 범주마다 갈리고 크기도 잡음 수준이다 — 기계 효과가 있다면 **한 방향**으로 나와야 한다.
splicing_connectors 만 0.996 으로 거의 결정적인데, 이 범주는 교란 자체에 둔감하다
(시드를 바꿔도 0.9958).

## 3. 기전 — `cudnn.benchmark = True`

`external/PSAD_official/train_normal_unet.py` 212~216행:

```python
cudnn.benchmark = True          # <- 212
seed = args.random_seed
torch.manual_seed(seed)
if torch.cuda.is_available():
    torch.cuda.manual_seed(seed)
```

- **`cudnn.benchmark = True`** 는 합성곱 알고리즘을 **실행 시각 측정으로** 고른다. 측정이
  잡음이라 **같은 기계에서도 선택이 달라질 수 있고**, 선택된 알고리즘 상당수가 backward 에서
  `atomicAdd` 를 써 부동소수 누적 순서가 실행마다 다르다.
- `torch.use_deterministic_algorithms` 는 설정돼 있지 않다.
- 시드는 **초기화와 데이터 순서**를 잡을 뿐 **연산 자체**를 잡지 않는다.

### 검증한 것 하나 — 증강 난수는 범인이 아니다

`dataset_2d_sup.py` 가 `random.choice`(70행)·`np.random.rand`(114·117행)를 쓰는데 학습
스크립트는 `random.seed`·`np.random.seed` 를 부르지 않는다. 처음엔 이것을 원인으로 의심했다.
**틀렸다** — PyTorch DataLoader 의 `_worker_loop` 가 워커마다 `random.seed(base_seed+id)` 와
`np.random.seed(_generate_state(...))` 를 심고, `base_seed` 는 시드된 전역 torch RNG 에서
나온다. 증강 난수는 시드로 재현된다.

## 4. 그래도 **아직 확정이 아니다** — 빠진 칸이 하나 있다

위 결과가 배제하는 것은 "기계가 지배적 원인" 이다. 배제하지 **못하는** 것:

> 같은 기계·같은 시드로 **다시 학습하면** 비트 단위로 같은가?

이것을 재지 않았다. 두 결말이 아직 살아 있다.

| | 같은 기계·같은 시드 재학습 | 함의 |
|---|---|---|
| **(A)** | Spearman ≈ 0.938 | 학습이 애초에 비결정적. **시드 고정이 재현을 보장하지 않는다.** 재현성 주장의 조건은 "다른 기계에서" 가 아니라 **"다시 학습하면"** 이다 |
| **(B)** | Spearman ≈ 1.0 | 기계 안에서는 시드가 실행을 고정한다. 그러면 기계 효과가 실재하되 그 크기가 우연히 시드 효과와 같다는 뜻이 되는데, cross_both 가 포화한 것과 잘 맞지 않는다 |

(가)·(나)를 보면 **(A) 가 유력**하지만 그건 추론이고, 3자 대조가 저지른 실수가 바로
"그럴듯한 기전을 재지 않고 적은 것" 이다. 같은 실수를 반복하지 않는다.

→ **3-f 복제 실행**으로 잰다: `docs/PREREG_psad_replicate_260823.md`
(5범주 × seed42 × 1회 재학습 ≈ 36분 × 5 = 3시간. 실행 전 사전등록.)

## 5. 논문에 주는 것 (3-f 결과 전 잠정)

3자 대조의 결론 **"분기는 안 맞고 융합은 맞는다"** 는 그대로다 — 바뀌는 것은 **왜** 다.

- 지금 말할 수 있는 것: "분기 점수는 재학습에 대해 Spearman ≈0.94 로 변동하며, 그 변동은
  **시드를 바꾸는 것과 같은 크기**다. 융합은 그것을 3.9배 흡수한다."
- 말하면 안 되는 것: "다른 기계에서는 분기가 재현되지 않는다" (측정이 이를 지지하지 않는다)

전자가 심사자에게 더 강한 진술이다. 기계 의존성은 변명처럼 들리지만, **"어떤 교란이든
분기는 ±0.94 로 흔들리는데 융합 수치는 시드 잡음 이내로 고정된다"** 는 §3.2 의 융합 둔감성
논지를 직접 뒷받침한다.
