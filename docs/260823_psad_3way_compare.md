# 260823 — PSAD 원단 재구축 3자 대조: **분기는 안 맞고, 융합은 맞는다** (5090)

3번(PSAD 원단 재구축) 최종 결과. 코드 `scripts/psad_rebuild/psad_3way_compare.py` ·
결과 `reports/countgd/psad_3way_compare.json` · 15/15 조합 전량 대조.

## 0. 이 실험이 답하는 질문

**"논문 수치가 재현되는가" 가 아니다.** 원본 hc(`d2_out_hc`)는 2026-06-30 생성이라 6/15 백업에
없어 **소실**됐고, 헤드라인 분기 구성의 test-free 수치는 애초에 재구축이 유일한 길이었다
(커밋 `1538e3b`). 260816 재구축도 원본과 1.08pp 격차를 남겼다.

여기서 재는 것은 **같은 절차를 다른 기계에서 돌리면 같은 값이 나오는가** 다.

## 2. 답 — **층위마다 다르다**

### 분기 수준: 재현되지 않는다

**Spearman 0.938** 이다(중앙 0.932, 최소 0.856). 같은 코드·같은 의사레이블·같은 설정으로
UNet 을 다시 학습했는데 **이미지 순위가 상당히 다르다.** 분기 단독 L+S 도 −0.0026 이다.

원인은 UNet 재학습이다. 300ep × 5범주 × 3시드를 처음부터 다시 돌렸다.

> **[260823 정정]** 이 자리에 처음 "시드는 고정했으나 GPU 커널·cuDNN 알고리즘 선택이
> **기계마다** 다르다" 고 적었다. **그 귀속은 근거가 없었고, 재보니 틀렸다.**
> `psad_variance_decomp.py` 로 같은 데이터에서 통제군을 뽑으니 —
>
> ```
> 시드만 다름 (같은 재구축본)    Spearman 0.9381
> 재구축만 다름 (같은 시드)      Spearman 0.9378
> 둘 다 다름                    Spearman 0.9374
> ```
>
> **기계를 바꾸든 시드를 바꾸든 divergence 가 같고, 둘을 겹쳐도 더 내려가지 않는다.**
> 즉 5090 재구축본은 260816 재구축본의 **또 하나의 시드와 통계적으로 구별되지 않는다.**
> 자세한 것은 `docs/260823_psad_variance_decomp.md`.

> 점수 **절대차**는 최대 1.85e+06 까지 나오지만 이 지표는 의미가 약하다 — PSAD 원점수는
> 정규화 전 1-NN 거리라 heavy-tail 이다(`20d1a92`: val ~0.6 vs test max 5.5e5).
> z-정규화 후 융합에 들어가므로 **순위(Spearman)** 가 실질 지표다.

### 융합 수준: 재현된다

**−0.0007.** 주 설정 시드 표준편차(0.0011)의 **0.61배**로, **잡음보다 작다.**

분기 단독 −0.0026 이 융합에서 −0.0007 로 줄어든다 — **3.9배 흡수**다.

## 3. 이것이 논문에 주는 것

`pc_backbone_swap`(백본 5종 교체 시 단독 폭 0.0553 → 융합 0.0080, **6.9배 압축**)과
같은 현상이 **재현성 축에서도** 나타난다.

> **분기를 통째로 다시 학습해 순위가 0.94 로 흔들려도 융합 결과는 잡음 이내다.**

이는 §3.2 의 융합 설계가 **분기 개별 품질에 둔감하다**는 주장의 직접 증거이고,
동시에 **재현성 주장의 정확한 형태**를 정해 준다 —
"분기 점수가 재현된다" 가 아니라 **"융합 수치가 재현된다"** 로 써야 한다.

## 4. 한계 — 범주별로는 잡음을 넘는다

전체 평균은 −0.0007 이지만 **범주별 차는 −0.0134 ~ +0.0091** 로 벌어진다
(screw_bag −0.0042, juice_bottle +0.0040). 평균에서 상쇄될 뿐이다.

따라서 **범주별 수치를 인용할 때는 재구축 간 변동이 시드 잡음보다 크다**는 점을 밝혀야 한다.
screw_bag 은 260816 재구축이 원본과 1.08pp 벌어졌던 바로 그 범주이기도 하다.

## 5. "논문값 대비" 표는 동어반복이다

| | 융합 L+S | Δ vs 논문 |
|---|--:|--:|
| 논문(정본) | 0.9723 | — |
| 260816 재구축(패키지) | 0.9723 | +0.0000 |
| 5090 재구축 | 0.9716 | −0.0007 |

260816 의 Δ +0.0000 은 **검증이 아니다** — 논문 수치가 바로 그 점수에서 계산됐으므로
같아야 정상이다. 의미 있는 비교는 **260816 ↔ 5090** 뿐이다.

## 6. val 꼬리 — 채택 판정 지표는 같은 영역에 있다

4.56 → 4.87 (+0.30). `PREREG_branch_improvement` §E2 가 기각한 하드 argmax 는 **22.21**,
채택한 소프트는 **5.67** 이었다. 5090 재구축은 채택 영역 안에 있다.

### 도구 결함 기록 (전부 수치 불변)

공식 코드가 옛 라이브러리 API 를 쓰는데 **연산 경로와 무관한 import** 가 패키지째 끌려와 막혔다.

| shim | 실체 |
|---|---|
| `apex` | import 만 하고 사용처 없음(364줄 중 2줄) |
| `pytorch_lightning.callbacks.base` | PL 1.x 경로 → 2.x 이동. 타입 주석 전용 |
| `torchmetrics.functional.auc` | `utilities.compute.auc` 로 이동만 |
| kornia 커널 shape | 0.8.2 가 `(1,33,33)` 반환 → `unsqueeze` 2회로 5D → `expand` 실패 |

넷 중 셋은 이름 이동이고 kornia 만 실제 shape 버그다.
